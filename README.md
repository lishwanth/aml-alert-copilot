# AML Alert Investigation Copilot

**Status: actively in development.** This README reflects the current build plan and what's live today — see the roadmap below for exact progress. Star/watch the repo if you'd like to follow along.

## The problem

Compliance teams at banks manually investigate huge volumes of anti-money-laundering (AML) alerts. Each investigation means cross-referencing structured transaction patterns against unstructured regulatory guidance, then writing a documented rationale for why an alert was escalated or cleared. Industry research widely cites that the large majority of AML alerts — often quoted at 90%+ — turn out to be false positives, which makes this an expensive, repetitive, and error-prone process at scale.

This project is a proof-of-concept copilot that surfaces the relevant structured risk signals for a flagged transaction, retrieves the specific regulatory guidance that matches its pattern, and drafts a citation-backed investigation memo — **for a human analyst to review and approve, never to auto-decide.**

## Data

Built entirely on the public [IBM Transactions for Anti-Money Laundering (AML)](https://www.kaggle.com/datasets/ealtman2019/ibm-transactions-for-anti-money-laundering-aml) dataset (CDLA-Sharing-1.0 license) — real, published, labeled transaction data generated by IBM's multi-agent simulation, not derived from or resembling any employer or client system. No proprietary or confidential data is used anywhere in this project.

Two "client" configs (`config/clients/`) map the same underlying dataset to two differently-shaped export formats (different column names, same real transactions) to demonstrate a config-driven onboarding pattern: adapting to a new client's data shape is a config change, not a code change.

## Design principle: not every step needs an LLM

This project deliberately splits work by what each tool is actually good at:

- **Deterministic validation** (Great Expectations) — schema, null, range, and duplicate checks on every record before anything downstream sees it.
- **Classical ML** (gradient boosting) — the first-pass screen across the full dataset at machine speed, using the dataset's real labels.
- **Deep learning** (graph neural network, stretch goal) — this dataset is a standard benchmark for GNN-based AML research, since laundering rings show up as graph structure across accounts and transactions.
- **LLM + agents** (LangGraph) — reserved for the last-mile reasoning step: investigating the small, pre-filtered set of transactions the ML/DL layers already flagged, retrieving matching regulatory guidance, and drafting the memo. Deliberately never runs across the raw dataset.

## Architecture

```
Raw data (Kaggle, real)
   -> Great Expectations validation  [deterministic]
   -> DuckDB staging + feature engineering
   -> Ingestion agent (schema drift / quarantine decisions only)   [LLM, judgment calls only]
   -> ML risk scoring (XGBoost/LightGBM)                            [classical ML, full dataset]
   -> GNN anomaly signal (stretch goal)                             [DL, full dataset]
   -> LangGraph investigation agents (flagged subset only):
        - Transaction Analyst agent  -> queries structured risk features
        - Compliance Research agent  -> RAG over public regulatory corpus (LlamaIndex + Pinecone)
        - Report Writer agent        -> drafts citation-backed memo, "draft for analyst review"
   -> Eval (Ragas: faithfulness, retrieval precision/recall + custom typology-match check)
   -> Observability (Langfuse: traces, cost, latency per agent step)
   -> FastAPI + Streamlit app -> containerized -> AWS ECS/Fargate
        (LLM inference for the public demo via Groq's hosted API;
         vLLM self-hosting exercised separately on a temporary GPU
         instance — see docs/ARCHITECTURE.md for the trade-off)
```

See [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) for the full design writeup, including the FDE-relevant config-driven adapter pattern and the deployment cost/data-governance trade-offs.

## Tech stack

Data & validation: PySpark/SQL, dlt, DuckDB, Airflow, Great Expectations
ML/DL: XGBoost/LightGBM, PyTorch (GNN, stretch)
GenAI: LangGraph, LlamaIndex, Pinecone, vLLM, Groq (hosted inference for the public demo), Ragas, Langfuse
App & infra: FastAPI, Streamlit, Docker, AWS (S3, ECR, ECS/Fargate, IAM, CloudWatch)
